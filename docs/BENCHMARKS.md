## How to read this

- **Ideal** is the best possible time if scheduling were free: tasks run in rounds of up to N ready tasks.
- **Efficiency** is ideal / actual. The gap is the orchestration overhead: scheduler wake-up, queue hops, the guarded database claims and status writes.
- A **chain** cannot go faster than its critical path however many workers exist. That is the dependency logic working, not a defect.
- Tasks here are sleeps. Real LLM tasks add variable latency, and a single local GPU may serialize them, so speedups on real agents are lower. These numbers isolate the runtime.
